Found as friction while the way the library is worked with was audited, and proposed by the user: simplify keeping the docs with scripts. Every change appended a paragraph at the same place of `docs/ROADMAP.md`, a free-text file of 1700 lines, so any two changes in flight conflicted at every merge -- on 2026-10-07 four pull requests did, and each was resolved by hand. A history entry is now one file, `docs/roadmap/<date>-<nn>-<slug>.md`, with a front matter (date, title, optional stage, `closes` -- the findings rows it deleted, `files` -- the files it names) and the paragraph as it should read; `scripts/gen_roadmap.py` renders them in file-name order between two markers of ROADMAP.md, and a change adds its own file, so there is nothing to conflict on. The entries are checked rather than trusted, by `--check` (its CI step is written and waits on the `workflow` scope of the push token -- the push over HTTPS that replaced the unreachable SSH was refused a change to a workflow file): the front matter is complete, the date is the one in the file name, every listed file exists, a findings row an entry says it closed is no longer in the findings (each of these four has a negative control that fails it, run once by hand: a wrong date, a missing file, a row still present, a stale rendering), and the generated block is up to date; `check_doc_file_refs.py` reads the entries too. The 14 entries of 2026-10-06 and 2026-10-07 were migrated with their text unchanged (the set of paragraphs before and after is the same), which also separates them into paragraphs: those inserted by hand were joined by a single newline and rendered as one. Older paragraphs stay where they are until they move. Not done: the findings table and the backlog tags as typed records, a check that a number in an entry is named with its test.
